# TEST PLAN DESIGN

## Test cases (Cucumber)
Each case test of the plan is coded as BDD under Cucumber tool (see [Cucumber doc](https://cucumber.io/docs/)).

Each test case is supported by a runner class based on TestNG plugin for Cucumber.

## Tests grouping (TestNG) 
TestNG tool is used for organization of Cucumber tests via groups with possible execution conditions (see [TestNG doc](https://testng.org/)).

A global TestNG test suite is maintained into `testng.xml` file (and aligned with each Cucumber Runner as bridge with TestNG) allowing test plan execution over TestNG (e.g; from IDE plugin for TestNG and Cucumber).

## Tests source code organization
- `src/test/java` folder
```
org.cybnity.application (root of test plan)
├── keycloak (integrated component based package name)
│   ├── admin.impl.test (sub-component or topic based packaged name; for e.g here about keycloak Admin implementation client)
│   │   ├── definitions (hosting of Cucumber scenario steps classes executing test cases specification)
│   │   ├── runner (hosting of bridge classes between Cucumber feature tests and TestNG)
│   │   ├── util (optional helper classes)
│   │   └── TestPlan (standalong test suite class relative to the full perimeter of tested sub-component or topic)
│   └── sso.impl.test (other tested sub-component or topic perimeter)
```

-`src/test/resources` folder
```
org.cybnity.application (root of test plan)
├── keycloak (integrated component based package name)
│   └── admin.impl.test.features (Cucumber feature files as scenario and test cases specification)
├── cucumber.properties (Cucumber configuration file)
├── env.properties (environment variables helper file regarding mandatory need values during test classes execution, and auto-completed via Maven profile)
├── test-jar-with-dependencies.xml (Maven assembly file supporting packaging of test jar and embedded dependencies for execution from command line)
└── testng.xml (TestNG tests suite regarding test plan) 
```

# TEST PLAN RUN

## Environment Variables Mandatory Definition

Environment variables need to be defined in the runtime system allowing dynamic configuration of CYBNITY components
integrated during the test plan execution.

The required variables are defined into a default `env.properties` file (dynamically feed from Maven profile enabled during build) allowing its customization per environment where
test plan can be launched. For example, developer can build project with dev-deploy-environment activated to collect a valued __env.properties__ file generated (in `target/test-classes` folder) with good values to set as environment variables on its workstation.

## Test Plan Execution

### Execution from IDE
Before to launch the `org.cybnity.application.keycloak.admin.impl.test.TestPlan` class of an individual TestNG runner (e.g; `org.cybnity.application.keycloak.admin.impl.test.runner.KeycloakRealmCreationTestCase`) from an IDE, add all variables defined by the `env.properties` file (version generated by Maven into `target/test-classes` folder and including values according to the test runtime context) into the unit test configuration.

### Execution from command line

To set tests context required variables on current system, execute file `set_environment_variables.sh` script or execute
manually:

```shell
set -a
. ./test-classes/env.properties
set +a
```

To show added variable to current environment, use command line:

```shell
printenv
```

#### Launch script
To execute the test plan, a global script ia available in the project which execute all the required tasks (e.g; environment variable updating, TestNG start action) for perform the test plan:
```shell
sh launch_test_plan.sh
```

#### Unit command line directives
Execution of Java application test plan over TestNG can be started via unique directives:

```shell
java -jar target/domain-layer-integration-test-plan-1.0.0-test-jar-with-dependencies.jar -testjar target/domain-layer-integration-test-plan-1.0.0-tests.jar
```

Specific test suite execution can be called via additional `-xmlpathinjar` argument:

```shell
java -jar target/domain-layer-integration-test-plan-1.0.0-test-jar-with-dependencies.jar -testjar target/domain-layer-integration-test-plan-1.0.0-tests.jar -xmlpathinjar testng.xml
```
